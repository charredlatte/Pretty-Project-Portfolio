## 1. Crisp scaling: `image-rendering`

- **Values (CSS Images 3, via MDN):** `pixelated` = nearest-neighbour up to the *nearest integer multiple*, then smooth interpolation to the final size; `crisp-edges` = nearest-neighbour only ("preserves contrast and edges"); `smooth`/`auto` = bilinear. Applies to **all elements and to images set in other properties** (so `background-image`, `border-image` and `<canvas>` all obey it) and "has no effect on non-scaled images".
- **Support, October 2026:** `pixelated` — Chrome 41+, Edge 79+, Safari 10+, Firefox 93+ (~97% global). `crisp-edges` — Firefox 3.6+ (prefixed early, unprefixed 65+), Safari 7+, and Chrome/Edge only from 148–149 (Chrome 149 stable 2 June 2026). Chrome's release note says Chrome, Firefox and Safari now treat the two as synonyms (nearest-neighbour). Prefixes go on the *value* (`-moz-crisp-edges`), not the property.
- **Write:** `image-rendering: crisp-edges; image-rendering: pixelated;` — `pixelated` last so it wins where both are understood. A single `pixelated` is enough in every 2026 evergreen browser.

## 2. Whole-number scaling at any devicePixelRatio

- `window.devicePixelRatio` = physical ÷ CSS pixels; it is **fractional on many devices (1.25, 1.5, 2.625)**, rises with page zoom but not pinch-zoom. Listen for changes with `matchMedia(\`(resolution: ${dpr}dppx)\`)` + `change`.
- **Compute the scale in device pixels, not CSS pixels:** `s = Math.max(1, Math.floor(Math.min(cssW*dpr/baseW, cssH*dpr/baseH)))`. Then either (a) `canvas.width = baseW*s` (device px) and `canvas.style.width = (baseW*s/dpr)+'px'` — the CSS size may be fractional, the device size is an integer; or (b) keep `canvas.width = baseW`, set the CSS size to `baseW*s/dpr` and let `image-rendering: pixelated` upscale. 7tonshark's recipe (`clientWidth * dpr / GAME_WIDTH`) is the DPR-aware one; Cinevva's `Math.floor(maxWidth / GAME_WIDTH)` ignores DPR and gives 1.5-px "pixels" at Windows 150 %.
- **MDN's rule for drawImage:** `dWidth` must equal `sWidth / xScale × n`, n an integer. Set `ctx.imageSmoothingEnabled = false` (default `true`) *before* each batch of `drawImage`. Size the canvas with the `width`/`height` attributes, not CSS, unless you want the pixelated upscale. iOS caps canvases at 4096 × 4096.

## 3. Animated pixel art

- **Canvas + rAF:** callbacks run at the display refresh rate (60, 75, 120, 144 Hz); MDN's warning: use the `DOMHighResTimeStamp` argument "otherwise the animation will run faster on high refresh-rate screens". Counting ticks (the dev.to "advance every 15 frames" sample = 4 fps at 60 Hz) doubles speed at 120 Hz. Use an accumulator: `frameMs = 1000/fps` (125 ms at 8 fps, 83.3 ms at 12 fps); `acc += t - last; while (acc >= frameMs) { frame = (frame+1) % n; acc -= frameMs; }`. rAF pauses in background tabs — the accumulator makes that harmless if you clamp the delta.
- **CSS `steps()`:** `steps(n)` = `steps(n, end)` (jump at the end of each interval; first frame held). Animate `background-position` from `0` to `-(n × frameW × scale)px` in **one** keyframe pair with `steps(n)`; duration = n / fps (8 frames at 8 fps = 1 s; 6 at 12 fps = 0.5 s). Jitter/half-frames come from interpolating `background-position` without `steps()`. Set `background-size` to the sheet size × integer scale and `image-rendering: pixelated` on the element. `animation-play-state: paused` stops it in place for reduced motion.

## 4. 9-slice dialogue boxes

`border-image: url(panel.png) 8 fill / calc(8px * var(--u)) / 0 round;` — **slice is unitless = source image pixels**; `fill` keeps the centre tile; `border-image-width` in px = slice × on-screen scale (unitless means a multiple of `border-width`; larger than `border-width` extends into padding). Set `border-style: solid` and a `border-width` — "some browsers don't render the border image if border-style is none or border-width is 0". Repeat: `round` tiles whole tiles (rescales, no clipping), `repeat` may clip a tile, `stretch` smears pixel edges, `space` leaves gaps. Make the content box a multiple of the tile size so `round` doesn't rescale. Assistive tech cannot read border images — decorative only. Alan Robinson's free browser tool "Pixel Art 9-Slicer 4-CSS" generates the snippet from a sheet.

## 6. Accessibility

- **Size:** WCAG sets no minimum font size, only 1.4.4 (200 % resize). Game Accessibility Guidelines use 28 px at 1080p as a floor. Practical: pixel fonts for titles, labels and buttons only; body text in a normal face. At m5x7's 16 px the x-height is 5 screen pixels — use 32 px. "Large text" (3:1 allowed) starts at 24 px, or ≈18.5 px bold.
- **Contrast on night scenes:** 4.5:1 normal text, 3:1 large text, 3:1 for UI components, icons and focus rings against adjacent colours (1.4.11). WCAG says to judge contrast *as if anti-aliasing were off* and that thin faces render fainter — exceed the minimum. Avoid pure `#fff` on near-black: web.dev suggests ~`rgb(250,250,250)` to stop glow/bleed. Put readable text on the opaque 9-slice panel, not on the scene.
- **Focus:** style `:focus-visible` (Baseline since March 2022, Safari 15.4+); the AAA floor is a 2-CSS-px-thick perimeter with 3:1 change between states. Pixel-style ring: `outline: calc(2 * var(--u)) solid var(--ink); outline-offset: var(--u)` in whole art pixels, square corners; or the two-colour ring `outline: 3px solid #000; box-shadow: 0 0 0 6px #fff` that works on light and dark. Keep `outline` (it survives forced-colors mode); never `outline: none` without a replacement.
- **Reduced motion:** `@media (prefers-reduced-motion: reduce)` pauses `steps()` sprites (`animation-play-state: paused`) and, in JS, `matchMedia('(prefers-reduced-motion: reduce)')` with a `change` listener stops the rAF loop. Reduce rather than remove; large panning/scaling (parallax, camera sweeps) is the vestibular trigger, small frame flips less so. Serve a static `<img>` via `<picture media="(prefers-reduced-motion: no-preference)">`.
- **Canvas hero and screen readers:** the HTML spec requires fallback content "that conveys essentially the same function or purpose"; canvas pixels are not in the accessibility tree. A decorative hero: `<canvas aria-hidden="true">` (never on or above a focusable element) with the real heading and copy in HTML next to it. A meaningful one: `role="img"` + `aria-label`. Don't put controls inside the canvas.

AVOID
- Don't compute the integer scale in CSS pixels: at devicePixelRatio 1.25/1.5/2.625 a 2× CSS scale is 2.5/3/5.25 device pixels — floor the scale in device pixels and derive the CSS size from it.
- Don't rely on `image-rendering: pixelated` to fix a non-integer scale: it snaps to the nearest integer multiple and then smooths, so edges still blur; the element size must be an integer multiple of the art.
- Don't count requestAnimationFrame ticks to time sprite frames — a 'every 15 ticks' loop runs 4 fps at 60 Hz and 8 fps at 120 Hz; use the timestamp and an accumulator (125 ms at 8 fps, 83.3 ms at 12 fps).
- Don't let `background-position` or `translate()` land on fractional screen pixels in a steps() sprite; keep frame width × scale, background-size and offsets in whole pixels, and animate the position in one keyframe pair with steps(N).
- Don't use `border-image-repeat: stretch` on pixel-art edges (it smears the pixels) or `repeat` when the box isn't a multiple of the tile (it clips); use `round` and size the box to the tile.
- Don't forget `border-style: solid` and a `border-width` with `border-image` — some browsers draw nothing otherwise — and remember slice values are source-image pixels, not CSS pixels.
- Don't put meaning in a border image or a decorative canvas: assistive technology cannot read either; keep the heading and copy in real HTML beside the canvas.
- Don't set `aria-hidden="true"` on a canvas (or any ancestor) that contains or wraps focusable controls; keep controls outside the canvas.
- Don't set a pixel font at a size that isn't its native multiple (Press Start 2P/Silkscreen/Tiny5 at 8n px, m5x7 at 16n, Monocraft at 9n, Micro 5 at 11n, Jersey 15/20/25 at 27/34/41n) — browsers antialias the stems and the look dies; `-webkit-font-smoothing: none` is macOS-only and non-standard.
- Don't expect Pixelify Sans or VT323 to be pixel-crisp at any size: Pixelify's blocks sit on a ≈11.1 px pitch with gaps, VT323 deliberately simulates CRT smear; treat both as 'pixel-look' display faces.
- Don't use Silkscreen for anything that needs lowercase — its lowercase codepoints draw as capitals — and don't typeset French with m5x7's curly apostrophe (U+2019 is missing; U+0027 is there).
- Don't treat m3x6 as an open licence: 'free to use with attribution' is a bare itch.io statement, not OFL/CC; its accent coverage is unverified. m5x7 is CC0, the Google Fonts faces and Monocraft are OFL 1.1.
- Don't set body copy in a pixel font: at m5x7's native 16 px the x-height is 5 screen pixels; use pixel fonts for titles, labels and buttons (16 px or more, 24 px+ to count as 'large text' for 3:1), body text in a normal face.
- Don't put text straight on a dark night scene: judge contrast as if anti-aliasing were off, aim above 4.5:1, avoid pure #fff on near-black (halation — use ~rgb(250,250,250)), and set UI text on an opaque panel.
- Don't style `:focus` instead of `:focus-visible`, and never `outline: none` without a replacement; the ring needs a 2 CSS px perimeter, 3:1 against adjacent colours and 3:1 change between states — draw it with `outline` (survives forced-colors) in whole art pixels.
- Don't simply delete animation under prefers-reduced-motion: pause the sprite in place (`animation-play-state: paused`, stop the rAF loop via matchMedia 'change'), serve a static frame, and especially drop large pans/zooms of the scene.
- Don't size the drawing canvas with CSS alone (it distorts) and don't exceed 4096 × 4096 on iOS — the canvas goes dead.
