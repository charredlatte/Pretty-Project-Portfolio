# The café's memory

Written 27 October 2026, from Charlotte's asks that day: "I don't want session memory in the kittychat cafe to
be only held by claude. The runner should keep memories compressed and compiled in the litter box on its own
after every session or chat ends. Once it goes dormant for more than 24 hours, it should run the litter box on
its own and be able to compress and compile all of that information and put it into the graphify style.
Documentation … also kept in the filing cabinets in the kitty Chat Cafe rooms", then, on whether a memory
expires, is superseded or merges: "Yes. All of the above. Really the memory should be organized into the each
filing cabinet of each project's room and then one overall memory that keeps the rules and preferences of the
user."

Nothing here is built yet. This page is the design, so the shape is settled before any code is.

## In plain words

Every cat that finishes a piece of work knows something the next one will have to learn again. Today that
knowledge dies with the session. The café's memory is where it goes instead: a short note per project, written
by the cat that learned it, filed in that project's room, and tidied into a map a later cat can read in one
go. On top of those sits one memory for the whole house: what Charlotte has asked for, in her own words.

It is not a transcript. It is what is worth keeping.

## Where memory is written, and by whom

**The cat writes it, at the end of its own turn.** The Stop hook (`harness/hooks/report.py`) already fires
there and already reports. Writing the memory then is nearly free, because the model has everything in its
head: it is not re-reading anything to remember it.

The runner cannot do this instead. It sees only what is in the café — each cat's `notes` and its latest
`said` — never a session's transcript, which lives in that session, not here. A queen summarising later would
cost more and know less.

The queen's own conversation is already in the café: every line is a `notes` document on the cat `queen`,
hers authored by `queen` and Charlotte's by `owner`. Claude Code's `--resume` holds only the working context,
not the record, so moving the runner to another engine (`docs/engine.md`) loses nothing here.

## The four kinds, and why nobody chooses a lifecycle

A memory's lifecycle falls out of what kind of thing it is. The cat labels the kind in one word; the rest
follows. This is what keeps "expires, supersedes and merges" from becoming mush.

| Kind | What it is | What happens to it |
|---|---|---|
| **Fact** | How something is: "the page's `MANOR` block is generated by `furniture.py`" | **Superseded.** When the code changes the old one is *wrong*, not merely old. Keyed, one current value. |
| **Decision** | A choice and its reason: "Cloudflare over Fly, for the free tier" | **Merges.** The history is the point. Never overwritten; a later turn appends "revisited on …". |
| **Observation** | What happened once: "the Windows CI leg took four minutes" | **Expires.** True then, noise later. |
| **Preference** | What Charlotte wants: "never credit Claude" | **Never expires.** Superseded only when she says otherwise. |

Only one of these needs judgement: whether a new fact supersedes an old one or both are true. That is a
`noul` for the `decide` tool, which the house rules already say should make this sort of call, and which runs
on Workers AI for nothing.

## The two homes

**Per project, in the room's filing cabinet.** A project's cabinet already shows its map (`graphs/<repo>`) and
its opening audit (`audits/<repo>`); its memory sits beside them. Facts, decisions and live observations for
that project, and nothing from any other.

**The house memory: Charlotte's rules and preferences.** One document, read by the queen every turn and handed
to cats in their briefs. This is the one that makes every other cat cheaper, because it is the context nobody
has to rediscover.

## The house memory looks like CLAUDE.md, and that is the point

`CLAUDE.md` is already a hand-maintained version of this document, and it works because of one convention:
**every rule cites her words and a date.** "her call, 20 October 2026: *Please stop updating the artifact*" —
not "the user prefers the Cloudflare link".

Keep that and the memory stays trustworthy. Drop it and it rots in a particular way: a model infers a
preference from one offhand remark, writes it down as settled, and reads it back as fact for ever. Confident,
wrong and self-reinforcing, with nothing in the file to argue with.

So: **a preference enters only with the quote and the date.** No quote, no preference — it is an observation,
and observations expire.

## The tidy-up, which costs nothing

When a project's cats have been dormant for more than a day, its memory is compacted. The gateway already
tracks each cat's `updated` and already has an alarm and an `AWAY` constant, so it is the right place to
notice; the runner is the right place to act.

The pipeline is four steps and only the first ever costs a token:

1. The cats' memory notes, already written at Stop, pile in the litter box. `litterbox/sort.py` files them by
   project; standard library, no model.
2. `graphify update` over that project's notes. graphify ingests documents, not only code, and needs no model.
3. `graph_doc.py` turns the graph into the `graphs/<…>` document a filing cabinet shows; standard library.
4. The `graph` tool saves it, keyed by the project, and it appears in that room's cabinet.

Expiring, superseding and merging happen on the way in: a date check, a keyed overwrite and an append.
Nothing there needs a model either.

## Compaction makes memory findable, never fewer

A compaction that *replaces* is how something that mattered disappears. The compiled memory links back to the
raw note, and the raw note stays in the litter box. `forget` already exists for cards that are filed or stale;
the same idea applies here, and it is the only thing that should ever delete.

## What is still to decide

- **The note's shape.** What a cat writes at Stop: the kind, the key, the claim, the files it touched, and —
  for a preference — the quote and date. Short enough that writing it is never a reason not to.
- **The slug.** Whether a project's memory extends `graphs/<repo>` or sits beside it as its own document, so
  the code map and the memory map do not collide in one cabinet.
- **How much is enough.** A cap per project, so a cabinet stays readable after a year.

## What this is for

Two things, and the second is worth more.

The queen stops depending on one engine's session store, which is what Charlotte asked for. And a cat starting
work reads what the last one learned instead of rediscovering it — which is the cheapest token in the café,
because it is the one never spent. A brief carrying the paths, the ruled-out paths and the acceptance check
costs its writer a few hundred tokens and saves its reader tens of thousands (`docs/delegation.md`).

Everything here lives under `harness/`, so building it waits for Charlotte.
