## Findings

- **The decider was never down, and the 5006 was a question with no words.** The 21 October note on this project's pile says `decide` answered `the decider failed: 5006: Error: required properties at '/' are 'model,state,questions'` both times it was asked, and that until it was fixed the house rule "The decider makes the judgement calls" could not be kept. It was a caller error, not an outage. Every Clef question needs `instructions`, its words; the gateway dropped any other key, so a question written the natural way (`{type: "noul", question: "..."}`) reached Clef as a bare `{type: "noul"}`, and Clef refuses such a body by naming the **root** — which is why all three root properties were present and the message still read as the service being down. #149 reproduced it, corrects the 21 October note, and makes both tools refuse a wordless question by name instead. Confirmed here independently: a `decide` call carrying `instructions` answered normally (`choice`, clef-flash, 521 input tokens). So `docs/engine.md` listing the decider as **Built** was right all along, and the three READMEs are not documenting something that does not run.

- **The decider's own answer on whether that note is settled came back under its floor, which is the protocol working.** Asked as the house rule asks (a `choice`, `kind: litterbox`, `old: waiting`, `floor: 0.6`, a `ref`), it chose `settled` with probabilities 0.7276 / 0.2724 — but a **confidence of 0.2072**. For a choice, `confidence()` in `decide.js` reads the `confidence` field, not the winning probability, so 0.2072 is the number the floor applies to and the decider did not decide. Falling back to my own judgement, as the rule then requires, and saying so: the note's question is answered, and the note goes stale the moment #149 lands. Worth keeping because the winning probability clearing 0.6 while the confidence does not is an easy thing to read the wrong way round.

- **"A probability for every allowed answer" was wrong for a `score`, and she has since asked for it to be fixed.** It was `decide.js`'s own header wording (line 2), restated in four places, exact for `noul` and `choice` only: a score comes back as one weighted number plus a confidence, with no per-level distribution. This note first handed it back to her as a judgement call, on the grounds that rewording a module's stated contract is not a docs fix. She asked for it directly on 23 October ("This needs to be clearer"), so #151 does it at the source and everywhere it was repeated, field by field per type, and also makes `decide` answerable by a chat model rather than only a System One one.

- **`harness/README.md` said a model id selects a local Laya. It does not.** The sentence read "Clef on Workers AI inside the free plan, Jev itself, or a local Laya, the model id being the switch". `decide.js`'s header separates the two cases: a model id is the only difference between **Clef and Jev**, both answered through the Worker's `AI` binding, while a local Laya is the **`DECIDE_URL`** branch instead. An operator following that sentence would set `DECIDE_MODEL` and never reach their own server. Pre-existing, not introduced by these pull requests; corrected in #146.

- **The decider was a row in the driver table.** `docs/engine.md` listed "Typed decisions (yes/no, a choice, a score) | Workers AI on the gateway, or any server in `DECIDE_URL` | Built" as the last row of its **Driver** table. It was also redundant: "What is already built" already carries the decider. Removed in #147, with a one-line note under the table so the answer sits where the question arises.

- **`README.md` named a function that does not exist, and the claim around it was also wrong.** It read "the command it builds is one function, `Turn.args()`, and another CLI means writing that function for it once". There is no `Turn` class in `harness/runner/queen.py` — the classes are `Gateway` (103) and `Runner` (115), and `args()` is at 247. "One function" is wrong too: `Runner.turn()` parses Claude Code's `--output-format stream-json` schema, `mcp_file()` writes Claude's `mcpServers` shape where Codex takes TOML, and `main()` resolves only `claude` and exits without it. Both halves corrected in #147. Worth noting because this sentence is what prompted the original question, so the docs had been teaching the misconception.
